- SHA-256：d82643d4ecce28fa2fb7f1a9ef79a48b5c954f04ece922f956efb8eedf824292。
- 5 个日志文件中，2 个仅为前一天启动记录；当日 3 份日志记录了 4 次录屏。原 ZIP 不修改，提取和统计在本目录 extracted/、car-results.json。
- 用户确认 E2 可持续显示手机高德/百度、切换应用后仍更新；车机触屏无效；需手动开旋转；长时间传视频画面延迟超过 1 秒。
- 最新声音对照：先打开车机音乐，再播放手机音乐，车机能够出声。导航播报并未因此自动获得实测结论。

## 触控证据

三份日志共有 164 条触摸相关消息：82 条真实事件和 82 条 comm 同步标记。真实事件为 21 次 down、21 次 up、40 次 move。

```text
motionevent3 214 185 0 50 down
motionevent3 0 0 0 0 comm
motionevent3 214 185 0 50 up
motionevent3 0 0 0 0 comm
```

A7 的 wl_apl_touch_single_point 分支（0x887f6 至 0x88802）将原坐标、0、50 交给 _send_point_hid；_mware_status_send_point2 将四个值输出为 motionevent3。证据位于 ../e3-input-audio-20261024/touch-input.asm.annotated.txt 与 touch-wire.asm.annotated.txt。

E2 只记录这类消息，没有实际手势注入。因此“车机没有回传触控”不成立。E3 接入已观察到的单指格式，并忽略 comm；其他指针不作猜测。手机全屏采集画面在 1280×480 中居中缩放，黑边不能直接换算成点击。E3 依据采集尺寸和手机屏幕尺寸映射，旋转过渡不一致时暂停输入。

## 延迟证据及限制

- A7 配置为 1280×480、config 30；E2 请求 30 fps、1,843,200 bps、两秒一个关键帧。K80 使用 c2.qti.avc.encoder，输出格式声明 latency=4。
- 每 5 秒的有效投屏统计中，encoded 与 videoWritten 差值最大为 1，dropped 均为 0；最长会话录屏从 09:55:20 至 10:03:24，超过 8 分钟。
- 这些计数表示手机编码和写出进展，不表示车机已经解码或显示。没有车机显示时间戳，不能量出端到端延迟，也不能排除内核、车机接收、解码或显示环节积压。
- 一条 USB_TX_STALLED 最终显示 pendingMs=0。旧代码在检查过程中两次读取会被写线程清零的字段，可能产生竞争；也可能在记录前写入恰好完成。因此不把这一条当成已证实的持续 USB 阻塞。
- 两处 USB EIO 关闭前出现车机切出/暂停消息；单凭日志不能判断是拔线、退出页面或其他关闭原因，不据此宣布协议异常。

## E3 的有限调整

1. 默认上限 15 fps、目标 1.2 Mbps，分辨率仍为 1280×480；保留界面开关，关闭后下次投屏按车机请求的帧率运行，便于对照。
2. 编码器请求低延迟和实时优先级；是否采纳看输出格式，不假设厂商一定接受。关键帧间隔一秒，拥塞恢复请求节流缩短为 300 ms。
3. 应用视频队列从 12 帧缩到 3 帧，超过 180 ms 丢弃依赖链并等待新关键帧，避免直接留下无法解码的 P 帧。该阈值不限制操作系统或车机缓冲，也不是端到端延迟保证。
4. 增加帧时间戳至编码输出的估算年龄、应用排队时间、整帧写入时间及各自最大值。修正写入计时的双读竞争。下次诊断可更好区分手机侧耗时和仍未观测的车机耗时。
5. 触控通过明确授权的无障碍服务执行，不读取页面文字；横屏通过用户授予修改系统设置权限后临时设置，停止时恢复原值。
6. 按用户要求暂停 USB 音频，不添加声音传输负担；已有成果见 ../../USB音频协议研究留档.md。

上述配置是待实车验证的改善尝试，未证明超过 1 秒的延迟已被消除。测试时先保持默认设置运行至少 10 分钟，在动态测试画面中用另一台设备同时拍摄手机与车机的计时数字；同一张图的数值差可估计显示延迟，包含约一帧采样误差。
