# E2 与 A7 协议通信复审

日期：2026-10-23（Asia/Shanghai）。本轮审查 E2 原版本，交付报告与复现材料；未改运行源码、未构建新 APK，未连接手机或汽车。

## 结论

**E2 的基础握手、当前 ext=0 的 WL 帧，以及 K80 已录制的视频形态，与这版 A7 接收逻辑匹配。SPS/PPS 分包修正有效，但还不能称为整车完整兼容。**

最应优先补齐的是 USB 写入停滞后的退出和恢复。另有非零扩展头、中途帧率重配置、辅助 NAL 排列三项条件性缺口，未在现有实车材料中触发，不能用来解释已发生的黑屏。

本轮将视频测试扩展至三段完整录屏：**2711 帧、66 个关键帧、2843 个 WL 视频包**。经 E2 原 Java 分包器和 A7 原 ARM 解析函数后，交付的视频字节逐帧一致。

## 需要处理的问题

### R1 / P1：USB 写入停滞只有日志，没有有界恢复

位置：[AoaTransport.java](../../src/main/java/org/opensaiclink/trial/AoaTransport.java) 的 writeLoop；[LinkService.java](../../src/main/java/org/opensaiclink/trial/LinkService.java) 的 tick。

控制消息和视频使用同一串行发送线程，可以避免数据交错。但底层 output.write 卡在视频载荷时，后续心跳也无法发送。tick 超过 3 秒只记录 USB_TX_STALLED，没有结束失效会话、清除“已配置”状态或进入恢复流程。

实际 E2 AoaTransport 注入阻塞输出流后：视频头已写出，载荷阻塞 3.2 秒，再排入心跳；输出仍只有 8 字节头，心跳未写出，transport 仍为 open。见 host-results.json 的 blockedWrite。

这复现了代码的失效行为，不证明物理 USB 阻塞原因。E1 会话 081630 曾出现编码 819、写出 2、丢弃 816；E2 是否会再次遇到这一问题尚未实车验证。

**下一版优先增加可中断或有期限的 IO、失效状态收敛和干净的会话重建。** 不能另开线程向同一 USB 流插入心跳，否则会破坏当前 WL 帧。

### R2 / P2，条件性：非零扩展头长度解释不同

位置：[WlFrame.java](../../src/main/java/org/opensaiclink/trial/WlFrame.java) Parser.feed。

A7 的 _mware_socket_thread 分别读取扩展区和正文，总长是 8 + ext + length。E2 以 8 + length 确定结束位置，再跳过 ext，等于把 length 当作包含扩展区。

构造 ext=2、length=3、正文 abc 的同一帧：A7 原函数读取 [8, 2, 3] 字节并完整交付；E2 只交付 a，余下 bc 滞留。这是可复现的边界差异。

**当前主通路 ext=0，未观察到实车触发该问题。** 后续应统一目标 A7 的长度定义，并测试带扩展区的后续粘包。此前“ext 一定包含在总载荷中”的泛化表述撤回；旧手机静态证据不能覆盖 A7 全部通道语义。

证据：[A7 分帧指令](wire.asm.txt) 的 0x7ac1c—0x7ad24；native-results.json、host-results.json。

### R3 / P2，条件性：新的 config 帧率未应用到运行中的编码器

位置：[WelinkSession.java](../../src/main/java/org/opensaiclink/trial/WelinkSession.java) config 分支；[LinkService.java](../../src/main/java/org/opensaiclink/trial/LinkService.java) configurationChanged；[ScreenEncoder.java](../../src/main/java/org/opensaiclink/trial/ScreenEncoder.java)。

先 config 30、开始录屏、再 config 10 时，E2 会更新 Status.fps；运行回调却只发送 onResumeWelink 并请求关键帧。编码器帧率仅在 start 初始化。直接从 APK 导出的回调也只有这两项动作：[DEX 证据](org.opensaiclink.trial.LinkService$4.apk-dex.txt)。

**收窄本轮初步判断：目前找到的 A7 config 调用在建链阶段。虽然有修改内部 fps 的入口，尚未确认正常播放中会再次下发 config；实车记录也只有初始 config 30。** 因而这是确定的重配置代码缺口，触发条件尚未在本车确认，不能作为当前黑屏原因。

若支持录屏期间重配置，应在编码输入侧限速或正确重配编码器，不能直接丢弃编码后的依赖帧来冒充限帧。

证据：[fps 设置入口](fps-setters.asm.txt)、[SDK 状态流程](sdk-state.asm.txt)、host-results.json。

### R4 / P2，条件性：AUD、SEI 连续位于 IDR 前时无关键帧回调

位置：[AnnexB.java](../../src/main/java/org/opensaiclink/trial/AnnexB.java) welinkPayloads。

E2 拆出 SPS/PPS 后，将其余 NAL 合成一个图像载荷。把合法 AUD、user_data_unregistered SEI 放在真实 IDR 前，A7 的有限查找没有继续找到 IDR，图像回调为 0。

**本次 K80 三段样本只有 SPS/PPS/IDR/普通帧，全部通过。** 此项约束其他编码器或未来变化，不能归因为这三段视频的失败原因。后续应明确辅助 NAL 策略，保证 A7 能识别图像，同时保留每帧的多个 slice。

证据：aud-sei-idr.bin、aud-sei-idr.wl；native-results.json 的 audSeiIdrImageCallbacks=0。

### 发送长度上限的边界差异

A7 原函数接受正文 1536000 字节，拒绝 1536001；E2 MAX_PAYLOAD 为 4194304。现有样本最大正文仅 40737 字节，未触及此边界。建议补齐对外发送上限，不把它作为当前故障原因。
