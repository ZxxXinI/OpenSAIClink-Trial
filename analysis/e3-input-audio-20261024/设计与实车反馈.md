# E3 触控、横屏与音频

## 最新范围（优先于下方初稿）

用户已通过“先开车机音乐，再开手机音乐”让车机播放声音。用户要求优先处理超过 1 秒的视频延迟，USB 音频暂停；已有协议整理到 ../../USB音频协议研究留档.md，不进入 E3 构建。下方音频方案为历史设计，不再执行。

新诊断包 OpenSAICLink-E2-1792809060649.zip 已收到并校验。真实触控为 motionevent3 x y 0 50 down/move/up，另有 0 0 0 0 comm；不能只实现旧的 motionevent。日志每 5 秒采样的有效投屏阶段，编码与发送差值至多 1 帧、丢帧为 0，不足以确认车机显示延迟的位置；保留分辨率并降低发送帧率，增加队列和写入耗时指标，实车再比较。

## 历史初稿

- 日期：2026-10-24，沿用 2026-10-21 任务目录。
- 用户实车确认：E2 可持续显示手机地图，切换应用后画面正常更新；未遇通信异常。触屏不能控制手机，投屏后音乐和导航均无声，需要手动开启自动旋转。
- 用户未验证退出投屏后的蓝牙音乐对照，且尚未导出本次诊断。因此声音根因未确定。
- E2 源码和构建信息快照：releases/E2-0.2.0/source-before-E3.zip；E2 APK 保留。

## 方案

1. 触控：A7 原函数输出 type 8 的 motionevent x y down/move/up。E3 增加明确授权的无障碍手势注入；只在投屏和 USB 会话有效且用户启用时处理。无障碍服务不读取页面文字或窗口内容。按视频实际居中缩放区域换算坐标，拒绝黑边区域。先支持单指；多指和其他格式保留诊断。
2. 横屏：仅声明自身横屏不能保证外部地图旋转。采用用户授予“修改系统设置”后，在投屏期间临时锁横屏；停止恢复原值，进程重启时清理未恢复状态；避免覆盖用户主动更改后的值。
3. 声音：强制切换车机蓝牙音源缺少证据，不发送猜测的切源命令。依据 A7 PCM 接收代码和原版封包，增加 USB 测试音及可选 AudioPlaybackCapture。用户开启后才请求录音权限并通过系统录屏授权。录制对象是允许捕获的应用播放声音，不采集麦克风。导航或受保护媒体可能禁止捕获，界面和日志明确显示限制。
4. 保持已实车通过的视频握手/分包主路径。新增触控与音频统计、音频设备/音量诊断，保留旧会话导出。

## 证据

- A7 _mware_status_send_point：motionevent；_mware_status_send_point2：motionevent3。原指令位于本目录 touch-wire.asm.txt。
- A7 wl_audio_protocol_analysis、get_audio_param、wl_audio_music_ctrl；原版 ByteUtil 的 16 字节包头加 8 字节音频参数；外层 WL type 17。
- [Android 手势服务](https://developer.android.com/guide/topics/ui/accessibility/service)
- [Android 系统设置授权](https://developer.android.com/reference/android/provider/Settings.System)
- [Android 播放声音采集限制](https://developer.android.com/media/platform/av-capture)

## 验收

- 主机测试：触控解析与黑边映射、PCM 字节布局与有界队列。
- A7 原 ARM 函数：验证新 PCM 参数和音频路径，并保留视频回归。
- Android 16 隔离模拟器：实际手势、横屏与恢复、媒体声音采集/停止、原视频功能回归。
- 新包的真实触控、车机声音和 K80 系统权限行为仍需驻车验收；不把模拟器成功当作实车完成。
